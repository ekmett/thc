# THC implementation guidance

Read `README.md` and `docs/contributing.md`. Preserve the existing AST and
bytecode backend contracts and the pinned GHC/Graal toolchain requirements.

## JVM runtime and primops

- Prefer Kotlin for handwritten JVM implementation. Keep Java where the Truffle
  Bytecode DSL, annotation processing, compiler behavior, or an actual Java/ABI
  boundary requires it; explain that requirement when adding Java code.
- Put simple primop behavior directly in its existing implementation or
  specialization. Remove forwarding-only helpers, redundant wrappers, and
  temporary result/carrier objects when their useful work can be inlined there.
  Moving the same unnecessary wrapper from Java to Kotlin is not the objective.
- Keep genuinely shared algorithms and semantic boundaries. Do not duplicate
  complex logic or weaken lifetime, ownership, synchronization, exception,
  context-isolation, or foreign-call guarantees to reduce the helper count.
- Use Kotlin inline helpers where they eliminate callback objects without
  obscuring those guarantees. Preserve `finally` cleanup and deliberate Truffle
  boundaries. Check generated bytecode or compiler graphs before claiming that
  allocations, boxing, dispatch, or calls have disappeared.
- Preserve exact vector species/representation proofs and typed fast paths.
  Avoid introducing inaccessible JDK-internal casts through Kotlin inference.
  Source simplification alone is not a performance result.

## Fixture generation and tools

- Prefer Haskell for GHC-facing exporters, fixture producers, native-oracle
  orchestration, and provenance. Prefer Kotlin for JVM-side checks and independent
  runtime models. Extend existing tools instead of adding another framework.
- Python is for a concrete Python-specific dependency or capability, not the
  default for scripting convenience. Do not add Python fixture generators,
  validators, or private development harnesses when Haskell/Kotlin reasonably
  fit. Existing Python tools may remain while their replacements are verified.
- Migrate cohesive producer/model/test groups and update every active caller,
  CI recipe, dependency fingerprint, and relevant guide. Retain positive and
  negative controls, strict Core audits, native oracle coverage, and provenance.
  Historical benchmark artifacts are evidence, not migration targets.
- Generate expected results independently with native GHC or a checked model,
  never with the THC implementation under test. Regenerate stale fixtures from
  their actual inputs; never edit hashes to bless an old artifact.

## Verification and handoff

Use small, reviewed, tested checkpoints. Exercise both backends and both handoff
modes when affected. Preserve failed evidence and state remaining limitations.
Do not replace first-compiled-call checks with warmup calls, retries, exclusions,
or weaker counters to obtain a passing result. Keep agents on owned worktrees
and coordinate shared build resources and integration with the task owner.
