# Working on THC

THC runs GHC Core on Truffle/Graal through AST and bytecode backends. Read
`README.md` for the supported toolchain and entry points, then
`docs/contributing.md` for the development workflow. Keep documentation about
current behavior and concrete next steps; remove obsolete implementation history.

## Source layout

- `src/main/java`: runtime, both backends, loaders and polyglot interop.
- `src/compiler`, `src/driver`, `src/cbd`: Haskell Core exporter, Cabal driver
  and compact binary distribution format. `src/runtime` contains the public
  Haskell runtime API.
- `src/build`: included Gradle build with Java build helpers; `src/gradle`:
  project Gradle script fragments.
- `src/tools`, `src/diagnostics`, `src/examples`: tool implementations,
  runtime diagnostics and examples. `bin` contains command entry points and
  supporting scripts; `etc` contains configuration.
- `nih/pinned`: version-pinned upstream submodules and generated support files;
  `nih/licenses`: third-party licenses; Gradle bootstrap files live in
  `nih/gradle/wrapper`. Preserve pinned revisions and attribution.
- `src/test`, `src/fullCoreTest`, `src/polyglotTest`, `t`: runtime tests,
  Haskell tests and native/Core fixture producers. Follow the nearest existing
  suite rather than introducing another harness.

## Implementation

Use Java for JVM code and Haskell for compiler-facing tools and fixture
producers. Gradle configuration is Groovy with Java helpers. Extend existing
Python tools when needed; use Haskell or Java for new harnesses.

Keep behavior at its owning operation or component. Remove forwarding wrappers,
redundant carriers and unused code; retain shared algorithms and real ownership,
lifetime, synchronization and ABI boundaries. Trust GHC's type checking after
lowering instead of repeating it at every operation. Preserve typed execution,
aggregate layouts, vector species, Truffle child ownership and context isolation.

Changes to calls, loops or lowering must preserve thunk sharing, PAPs, tail-call
handoffs, exception masking, resumable continuations and foreign-call safety.
Consult the relevant runtime guide and existing tests before changing these
contracts. Inspect generated bytecode or compiler graphs before claiming that
boxing, allocation or dispatch has disappeared.

Public Haskell APIs need Haddock documentation, examples where useful, and the
project's SPDX/module headers. Keep the convenience facade `Safe`; hazardous
`THC.Internal` modules must be explicitly `Unsafe`. Use `Trustworthy` only for
an audited typed boundary with explicit exports and documented effects.

## Build and verification

Use the pinned GHC and GraalVM versions in `README.md`; initialize the upstream
submodules before building. See `docs/windows.md` for native Windows setup.

- `make`: build runtime and Haskell components; `make runtime` and `make haskell`
  build them separately.
- `make test TESTS='thc.RuntimeTest'`: prepare fixtures and run a selected class.
- `make test-modes TESTS='thc.RuntimeTest'`: prepare fixtures once and run both
  handoff modes. With prepared fixtures, combine `testDefault` and `testDense`
  in one Gradle invocation with `--continue` and selectors for each task.
- `make lint-haskell`: lint tracked Haskell sources. Do not lint fixtures,
  upstream sources or frozen evidence.
- `make docs` and `make docs-check`: build and check the documentation site.

Test the behavior changed, including both backends and handoff modes when
applicable. Derive expected results independently with native GHC or a checked
model. Regenerate stale fixtures from their inputs; never bless them by editing
hashes. Preserve first-compiled-call checks, negative controls and failed evidence;
do not substitute warmup, retries, relaxed limits or weaker assertions.

Use focused checks during development and reuse verified results for unchanged
code. Record the exact revision, commands and outcomes. Keep known behavioral
limits in the relevant guides, including `docs/primop-behavior.md`; update affected
capability metadata and generated documentation when the contract changes.
Benchmark against native GHC where possible. Keep development benchmark results
private unless the user requests publication.

## Collaboration and integration

Work in an owned checkout and preserve unrelated changes. Coordinate overlapping
files and builds; use per-worktree build leases rather than a global build queue.
Publish tested worker branches promptly with their dependencies and evidence.
The designated integrator reviews and merges onto current main with a normal
fast-forward push; do not force-push or change branch protections.

Reuse worker evidence and retest substantive integration changes. GitHub Actions
provide post-merge feedback, not a publication gate; address failures promptly.
Keep automated bulk merging disabled. Report verified behavior and remaining
limits without claiming that preparation alone proves execution or compilation.
