# Matching-root tail handler audit

This is a source audit, not a claim about the resulting machine graph. Exact frozen THC candidate source and JAR hashes are in `../typed-tail-v1/manifest.json`. The earlier bytecode implementation is frozen in `../bytecode-v3/manifest.json`.

Cadenza's AST is the guide. `src/cadenza/jit/nodes.kt:142` initializes the root bloom, executes the body, catches a tail call matching the root's shared body identity, restores captures/arguments and enters its local self loop. `src/cadenza/jit/tail_calls.kt:210` repeats that same matching-root catch. This handles a multi-root cycle as well as syntactic self recursion.

For A → B → A, A's initial bloom is incoming ancestors OR A's mask. A's tail call passes that to B. B's call toward A detects the mask and throws before publishing an outgoing packet header. B does not own A and rethrows. A restores the packet's captures and formal arguments into its original activation and continues there. Its original ancestry must remain unchanged. Reading the packet header, accumulating the intermediate B ancestry, or clearing the bloom on that backedge would break the intended behavior. In A → B → C → D → E → C, C retains its original A/B/C ancestry as it loops across D/E.

THC's AST has the equivalent handler in `runtime/Program.kt:469` and `SelfRepeater`; shared identity/mask are in `runtime/GuestRoot.kt`. The frozen old bytecode root implemented a direct-self fast branch but lacked the transitive matching-root handler. The candidate's `BytecodeRoot.Apply` catches only tail applications and only matching shared body identity, returning an internal TailCall value. `BytecodeProgram.application` consumes it, restores lexical locals and emits a branch to an actual Bytecode DSL While backedge. It preserves the original root bloom and ignores the bounce packet's uninitialized header. Every tail application enables the loop; this is intentionally broader than direct-self arity eligibility.

Non-tail DirectCaller/IndirectCaller and thunk Force boundaries reset ancestry and contain bounces locally. They must finish pending work and thunk update/failure memoization. The first saturated segment of overapplication is also non-tail, so a bounce in that segment cannot be intercepted by the enclosing root while skipping remaining arguments. The final segment uses the original tail flag. PAP dispatch constructs a saturated packet containing captured environment, previously supplied prefix and fresh suffix; restoration must use full formal indexes, including unused-formal holes. Root clones retain bodyIdentity, so target object identity is insufficient. Captured environments remain dynamic values and must be refreshed on each reentry.

The local Apply handler covers every escaping tail source in the current compiler: Force and non-tail application already contain their bounces. This assumption must be revisited if another bytecode operation begins throwing an escaping TailCall. The internal TailCall result is not a guest value.

API constraint: the generated Graal Bytecode DSL `resolveThrowable` explicitly rethrows ControlFlowException; `beginTryCatch` handles AbstractTruffleException. The existing interceptor can return from a root, but cannot itself resume at an arbitrary bytecode PC. A local operation catch followed by emitted bytecode branching avoids an outer host trampoline. Cadenza's experimental bytecode interceptor is not evidence that its AST matching-root behavior was implemented there.

Actual graph validation remains necessary: the matching-root predicate should fold for fixed inlined targets; the bounce and argument packet should scalar-replace; primitive count/accumulator values should flow through native backedge phis. The synthetic fixtures and `capture.sh` preserve PE and scheduled before-high/after-mid evidence for those checks. A passing deep recursion test proves stack safety, not these optimization properties.
