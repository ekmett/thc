# GHC's late unsafe-equality case rule

The exporter applies GHC 9.14.1's own `GHC.Core.Utils.isUnsafeEqualityCase` predicate to the original typed Core case, before erasing type/coercion arguments or binder occurrence information. This is the same rule used by `GHC.CoreToStg.coreToStgExpr`: one `UnsafeRefl` data alternative, a dead case binder, and the actual wired `unsafeEqualityProof` identity applied to its three arguments. A matching case exports its RHS. The optimized GHC program itself is not mutated or resimplified.

The surviving expression keeps the case's result representation and its source notes. Its `unsafeEqualityCase` metadata records the exact late rule; `sourceCore` continues to contain the original Core. Interface dependency discovery applies the same predicate, so erased proof cases do not create a spurious dependency on an unavailable executable proof body. No runtime primitive, synthesized proof value, or name-based alias is added.

A bare proof, live case binder, wrong callee, or wrong alternative does not match. GHC's original `unsafeEqualityProof` source is deliberately self-recursive before CoreToStg, and supplying that unlowered body is not evidence of working execution. This change does not supply a general first-class proof definition. The genuine `firstClassProof` and `liveBinder` fixtures remain strict missing-definition frontiers. Ordinary nonmatching cases still evaluate their real scrutinee; the wrong-callee fixture raises its original guest exception.

`cabal run exe:thc-fixtures --offline -- unsafe-equality` builds a fresh native GHC oracle, checks 49 rows against independent wraparound formulas, and exports/audits both pre- and post-Tidy boundaries. It requires retained lowering evidence in an unlifted `IntRep` identity, a lifted payload cast, a mixed tuple result, nested erased proof cases, and the actual installed `unsafeCoerce` unfolding. The payload tests retain unused bottom fields and arguments. Twelve direct GHC API controls check the structural predicate, including a binder whose deadness must be recovered, a same-spelling identifier with a different wired key and erased/missing/extra arguments.

`UnsafeEqualityTest` checks AST and bytecode with normal and disabled inlining. Every native row after explicit compilation requires the exact number of compiled guest entries and valid original, host, and observed active targets. Both raising controls verify installed targets before the call, the intentional `raise#` invalidation afterward, unchanged exception payload identity, and released result/argument storage. Always-throwing graphs can deopt before entry instrumentation; these are deoptimization controls, not compiled-value execution claims. The complete native/compiler/auditor inputs and generated artifacts are hashed; clean-checkout preparation and CI retain these checks.

This is one compiler-boundary fix, not full Typeable or ErrorCall coverage. The original Typeable fingerprint path still exposes nonempty tuple inputs, pinned allocation, raw-address/lifetime operations, and MD5 FFI dependencies.
