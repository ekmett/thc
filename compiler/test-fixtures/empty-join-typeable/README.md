These are complete, unmodified historical GHC 9.14.1 exports from the original
`GHC.Internal.Data.Typeable.Internal` source, before and after Tidy. The gzip
files retain every binding and cold branch; no dependency closure was pruned.
`provenance.json` records compressed and original hashes, original compiler
source hashes, installed toolchain details, and the pinned upstream source URLs.
The original Typeable source, Fingerprint boot interface and GHC library license
are retained beside them.

The source export was generated by compiling the unmodified source with `-c
-dynamic -fforce-recomp -this-unit-id ghc-internal -package ghc-internal -O2 -g
-dcore-lint`, using an interface overlay of the installed ghc-internal `.dyn_hi`
files symlinked as `.hi` (except the Typeable module itself), after compiling
`Fingerprint.hs-boot` into that overlay. The plugin options were `source-notes`,
`closure=fpTYPELiftedRep`, `closure=mkTrCon` and, for the post export,
`post-tidy`. The plugin's exact historical source hashes are preserved; these
files are deliberately not relabelled as exports of the current compiler.

Run `python3 scripts/test-empty-join-inputs.py` from the repository root. It
verifies retained hashes, decompresses the complete modules and audits both
roots. Disabling the empty-join capability yields six formal and 34 call-site
rejections. Enabling it removes only those issues: all 28 missing globals remain,
and both stages still fail the strict audit. This is a source-backed frontier
regression, not a claim that Typeable executes.
