# Dense handoff checkpoint, reference extension (v3)

The isolated prototype passes **186/186 tests with handoff enabled and 186/186 in the default control suite**. Main THC is unchanged. This checkpoint extends the validated scalar mailbox to supported single-reference results and stops further performance campaigns in favor of broader real-GHC coverage.

The runtime diff from v2 is small: HandoffEntry records whether the result is primitive Long, permits a single boxed result representation, and leaves reference roots on the existing FunctionBody.execute path. Scalar roots alone publish the private completion token/register. Every typed caller decodes that exact private token immediately; any other Object returns unchanged. The tail trampoline uses the same decode. No returned reference is stored in context state, no new forcing is introduced, and argument ownership, generation guards, snapshots, reference clearing, and separate scalar return lifetime remain unchanged.

Input storage is still an interned mutable generated class keyed by physical field vector (Long/reference), with identical dense fields in interpreted fallback. The single-loan mailbox depends on all arguments being evaluated/staged before acquisition and fully copied/released before guest body execution. The real Truffle call still accepts shared empty Object[] and returns Object; this is a language memory protocol, not a physical multiple-register ABI.

Three new tests cover:

- Four reference inputs, lazy ignored arguments, exact DataValue identity and nested outstanding reference results; ordinary boxed Long returns ignore stale scalar-register values; mixed Long/Object return routes work in both directions.
- Deep self/interior/outward reference-result tail cycles, captured returned closures and immutable lazy PAP prefixes, with AST handoff and bytecode differential fallback.
- Reference snapshots retained across input release, exception, explicit compiled deoptimization, and later carrier reuse; natural boxed result identity; cleared free reference fields.

The prior scalar tests still cover deep non-tail recursion, bloom ancestry, multiple ancestor cycles, physical representation aliases, independent storage and retained primitive snapshots. AstSelfCallTest contains the reviewed cold-loop deoptimization/recompile strengthening described in v2; no compiled-execution assertion is silently removed.

A bounded one-second-warm/100ms **smoke check**, not steady-state throughput evidence, validates the reference probe and allocation behavior. It creates four fresh Box inputs before each call, consumes all payloads, and returns either one input object or a fresh Box. A full System.gc collection precedes warmup so the retained mailbox survives while later payloads are young; logs record one aging collection. Residual allocation is112→80bytes/topcall for shared return and128→96bytes for fresh return. With guest inlining enabled, control0/16bytes becomes80/80bytes: escaping input storage prevents elimination of input objects. These numbers expose a real tradeoff; no reference throughput claim or rollout decision follows. Raw smoke results retain their explicit smoke-only/validSteadyState=false status. No additional v3 graph or long timing campaign was run after the coverage pivot.
